# 로드맵

각 단계는 "학생이 실제로 써볼 수 있는 상태"를 종료 조건으로 한다. 단계 순서는 의존성 순서다: 공압이 캔버스·배선·유체 솔버의 기반을 만들고, 전기가 연동(솔레노이드·리밋 스위치)을 추가하고, 유압은 유체 솔버를 재사용하고, PLC는 전기 I/O 위에 올라간다.

## Phase 0 — 기반 (에디터 뼈대) ✅ 완료 (2026-07-12)

- Vite + React + TS 프로젝트 셋업, `core/` · `ui/` 구조
- 문서 모델 + JSON 직렬화/역직렬화 (스키마 버전 포함)
- 캔버스: 그리드, 팬/줌, 부품 배치·이동·회전·삭제, 직교 배선, 스냅
- 부품 정의 레지스트리 + 속성 패널 자동 생성
- 파일 저장/불러오기 (.json 다운로드/업로드)
- undo/redo

**완료 기준**: 더미 부품 두 개를 놓고 배선해 저장→불러오기 왕복이 되는 것.

## Phase 1 — 공압 ✅ 완료 (2026-07-13)

- 공압 부품 라이브러리 (PRD 4.1 전체) + ISO 1219 기호 SVG
- 유체 솔버 + 실린더 적분 + 고정 틱 엔진
- 시뮬레이션 모드: 수동 밸브 클릭 조작, 가압 라인 색상, 밸브 스풀·실린더 애니메이션
- 실행 전 검증 (미연결 포트, 압력원 부재)
- 내장 예제: 기초 공압 회로 5~10종 (단동 실린더 직접 제어, 5/2 밸브 왕복, 속도 제어, 셔틀/2압 논리)

**완료 기준**: 순수 공압 시퀀스(공압 파일럿 방식 A+A-)가 작도·시뮬레이션되는 것.

## Phase 2 — 전기 + 전기공압 연동 ✅ 완료 (2026-07-13)

- 전기 부품 라이브러리 (PRD 4.2) + 사다리형 전기 회로도 영역
- 전기 연결성 솔버, 릴레이/타이머/카운터 상태 기계
- 도메인 연동: 솔레노이드→밸브 전환, 실린더 리밋 스위치→접점
- 내장 예제: 자기유지, 인터록, 타이머 회로, 전기공압 A+B+A-B- (공유압기능사 실기 유형)

**완료 기준**: 공유압기능사 실기 유형의 전기공압 시퀀스 회로가 동작하는 것.

## Phase 3 — 유압 ✅ 완료 (2026-07-13)

- 유압 부품 라이브러리 (PRD 4.3 — 4/3 클로즈드/탠덤/오픈 센터 포함), 유체 솔버에 탱크 귀환·중립 센터 타입 반영
- 내장 예제: 유압 기초 회로 (실린더 왕복, 감압+압력 스위치, 미터아웃). 릴리프 압력 상한은 솔버 동작+테스트로 검증 (codex-review H6 반영). 미터인·카운터밸런스 전용 예제는 후순위

**완료 기준**: 4/3 밸브 + 복동 실린더 유압 회로가 전기 제어로 동작하는 것.

## Phase 4 — PLC 래더 (교육용 LD, XG5000 표기 관례 참고) ✅ 완료 (2026-07-13)

- 래더 모델 + 셀 그리드 에디터 (접점, 코일, SET/RST, TON/TOFF/CTU/CTD 기능블록, 렁 편집)
- 스캔 실행기 + P 디바이스 I/O 매핑 테이블 UI
- 모니터 모드 (통전 오버레이)
- 내장 예제: 자기유지, 타이머 시퀀스, 전기공압 회로의 PLC 치환 예제

**완료 기준**: Phase 2의 릴레이 시퀀스 예제를 PLC 래더로 동일하게 재현할 수 있는 것.

## Phase 5 — 장비 뷰 + 마감 ✅ 완료 (2026-07-13)

- 일러스트 장비 뷰 (프로파일 보드): 공압 우선, 회로도와 스플릿 화면 동기화
- 예제 브라우저 정리 (카테고리: 기초 공압 / 전기공압 / 유압 / PLC / 자격증 유형)
- 성능 점검 (부품 100개 60fps), UI 폴리시(한국어 문자열 정리, 단축키, 인쇄용 회로도 내보내기)

**완료 기준**: 수업 1차시 분량의 데모 시나리오를 처음부터 끝까지 시연 가능한 것.

### 구현 노트 (완료 시점 상태)

- 장비 뷰는 공압/전기 주요 부품 16종의 일러스트 스프라이트 제공, 미등록 부품은 기호로 폴백. 뷰포트를 회로도와 공유해 팬/줌 동기화되며 시뮬레이션 중 스프라이트를 직접 클릭해 조작 가능.
- 예제 18종을 카테고리(공압 기초/전기공압/유압/PLC/자격증 유형)로 분류.
- 성능: 부품 100개 + 배선 100개 회로에서 엔진 평균 틱 시간 5ms 미만 (테스트 상시 검증).
- 인쇄용 SVG 내보내기 지원 (그리드 제거, CSS 변수 인라인).
- (기록 당시의 미구현 잔여였던 장비 자유 배치·감압밸브·유압 모터는 Phase 8·7·10에서 구현 완료됨)

## Phase 6 — 변위단계선도 ✅ 완료 (2026-07-13)

- 시뮬레이션 중 실린더별 위치(0~1)를 시간축으로 기록하는 레코더 (core, React 무관)
- 계단형 선도 차트 패널: 실린더별 트랙(이름표 병기), 실행 시 자동 기록·초기화
- 자격증 실기의 시퀀스 설계 검증(A+B+A−B− 파형 확인)이 목적

**완료 기준**: A+B+A−B− 예제 실행 시 두 실린더의 계단 파형이 순서대로 그려지는 것.

## Phase 7 — 압력 레벨 (준정량 최소 확장) + 감압밸브 + 압력 스위치 ✅ 완료 (2026-07-13)

- 유체 솔버가 가압 전파 시 **압력 레벨(bar 수치)**을 함께 전파 — 수치 해석이 아니라 경로상 최소 레벨 전파(min-cap)로, 논리/상태 기반 결정을 유지하는 최소 확장
- 감압밸브(유압): 통과 시 레벨을 설정값으로 제한
- 압력계: 배관 레벨 수치 표시
- 압력 스위치(공압, PRD 4.1 잔여): 유체 포트 압력이 설정 레벨 이상이면 전기 접점 동작 (유체→전기 연동)

**완료 기준**: 파워유닛(40bar) → 감압밸브(20bar) → 압력계가 20을 표시하고, 압력 스위치로 램프가 켜지는 것.

## Phase 8 — 장비 뷰 자유 배치 ✅ 완료 (2026-07-13)

- 문서에 `equipmentLayout`(부품별 장비 뷰 좌표) 추가 — schemaVersion 2 + 마이그레이션
- 장비 뷰에서 스프라이트 드래그로 자유 배치 (편집 모드), 배치 초기화 버튼
- 호스/배선은 이동된 포트 위치 기준으로 재라우팅

**완료 기준**: 장비 뷰에서 부품을 옮겨 저장→불러오기 후 배치가 유지되는 것.

## Phase 9 — PWA + 로컬 저장소 (백엔드 준비) ✅ 완료 (2026-07-13)

- PWA: 매니페스트 + 서비스 워커(정적 자산 캐시)로 오프라인 실행, 설치 가능
- 저장소 어댑터 인터페이스(list/save/load/delete) + 브라우저(localStorage) 구현 — 파일 없이 회로 저장/열기
- **실제 서버(계정·클라우드·과제 배포)는 "백엔드 없음" 고정 결정에 저촉되므로 사용자 확인 전 착수 금지.** 어댑터 인터페이스가 향후 REST 구현의 접점.

**완료 기준**: 브라우저 저장/열기가 동작하고, 프로덕션 빌드가 오프라인에서 로드되는 것.

## Phase 10 — i18n 기반 + 유압 모터 ✅ 완료 (2026-07-13)

- 문자열 리소스 모듈(t(key), ko/en 사전) + 언어 전환 토글 — UI 크롬(툴바·패널·상태바) 우선 적용, 부품·예제 이름은 후속(한국어 유지)
- 유압 모터: 액추에이터 behavior 확장(정/역회전), 기호 회전 애니메이션

**완료 기준**: 언어 토글로 UI 크롬이 영/한 전환되고, 유압 모터가 밸브 방향에 따라 회전 방향을 바꾸는 것.

## Phase 11 — 실행 모드 분화: 연속동작 / 구분동작 ✅ 완료 (2026-07-14)

- **연속동작 실행**: 기존 실행 방식 (50Hz 고정 틱 연속 진행)
- **구분동작 실행(스텝 모드)**: 실린더가 한 "동작"(행정 완료 또는 중간 정지)을 마칠 때마다 시뮬레이션이 자동 일시정지되고, **빈 캔버스 클릭**(또는 [다음 동작] 버튼)으로 다음 동작을 진행
  - 동작 경계 판정: 실린더가 행정 끝(0/1)에 도달하거나, 움직임이 멈춘 채 일정 시간 유지될 때 (core `StepController`, React 무관)
  - **사이클 경계 표시**: 모든 실린더가 초기 위치로 복귀하면 "사이클 완료 — 처음 동작으로 돌아감"을 상태바에 표시 (마지막 동작→처음 동작 전환 지점)
- **변위단계선도 연동**: 동작 경계마다 번호(① ② …) 세로 점선, 사이클 경계는 강조 실선(↻)으로 표기 — 구분동작으로 진행한 시퀀스를 선도에서 단계별로 읽을 수 있게

**완료 기준**: A+A− 예제를 구분동작으로 실행해 클릭마다 A+ / A−가 하나씩 진행되고, A− 완료 시 사이클 경계가 상태바·변위선도에 표시되는 것.

## Phase 12 — 학습 활동 설명 필드 (과제물 JSON 메타데이터) ✅ 완료 (2026-07-15)

**배경**: 학생이 과제물을 .json으로 저장해 제출하면, 교사는 파일을 열어보기 전에는
그 회로가 어떤 학습 활동인지 알 수 없다. 파일 안에 활동 설명이 글로 들어 있으면
교사가 학습자별 누적 자료를 분류·활용할 수 있다.
(예: "제어밸브 및 복동실린더를 활용한 시퀀스 제어", "속도제어 밸브·푸시버튼·릴레이를
활용한 속도제어 회로 구현")

### 설계 결정 (소유자 인터뷰, 2026-07-15)

- **작성 주체 — 자동 초안 + 수정 가능**: 앱이 회로 내용에서 설명 문장을 자동 생성해
  초안으로 제시하고, 학생·교사가 저장 전에 수정할 수 있다. 필드를 비워둔 채 저장하면
  자동 초안을 채워 저장한다 (설명 없는 파일이 생기지 않도록).
- **학습자 식별 정보(이름/학번/반) 전용 필드를 두지 않는다**: 이름·학번을 위한 전용
  입력 필드를 만들지 않고, 자동 생성기도 식별 정보를 만들지 않는다. 제출자 식별은
  파일명·제출 체계(LMS 등)에 위임한다. 이 결정은 문서 포맷의 non-goal로 유지한다.
  단, 학습 활동 설명·회로 제목·부품 이름표는 자유 입력이라 학생이 개인정보를 적을 수는
  있으므로 "포함하지 않는다"는 기술적 보장이 아니라 "전용 필드 없음 + 서버 미전송 +
  자유 입력란 주의 안내"가 정확한 설명이다 (review P1). 파서는 미등록 `meta` 키를
  제거해 조작된 JSON의 숨은 식별 필드가 재직렬화되지 않게 한다.
- **범위 — 포맷 + 입력 UI까지**: 여러 JSON을 일괄 열람하는 교사용 뷰어는 이번
  범위에서 제외하고 후순위 후보에 등재한다.

### 구현 계획

1. **스키마 (v2 → v3)**
   - `meta.learningActivity?: string` 필드 추가 (한국어 설명 문장, 길이 상한 예: 500자).
   - `schemaVersion: 3` + `migrateV2toV3` (v2 문서는 필드 없음 → 빈 값으로 로드,
     다음 저장 때 자동 초안이 채워짐). CLAUDE.md의 "포맷 변경 시 마이그레이션 추가"
     규약과 equipmentLayout(v1→v2) 전례를 따른다.
   - `parseDocument` 검증: 타입(string)·길이 상한. 기존 검증 스타일(propertySchema
     기반 정규화)과 일관되게.
2. **자동 초안 생성기 (core, React 무관)** — `src/core/model/learning-activity.ts`
   - `summarizeLearningActivity(doc): string` — 부품 정의의 role/domain을 집계해
     "[주요 부품 나열]을(를) 활용한 [제어 유형] 회로 구현" 형태의 문장을 조립한다.
     부품은 우선순위 2단계(유체 액추에이터·밸브·능동 elec-load가 우선, 접점·표시등은
     후순위)로 정렬해 배선용 리밋스위치·릴레이접점 다수가 핵심 부품(실린더·밸브)을
     밀어내지 않게 한다. 동력원/배기/분기 역할은 목록에서 제외.
   - 제어 유형 판정 순서(데이터 주도, 부품별 분기 금지): PLC 프로그램 존재 → "PLC 제어"
     / 솔레노이드 밸브 → "전기공압(유압) 시퀀스 제어" / 롤러·리밋 스위치 → "시퀀스
     제어(자동 왕복)" (실린더 개수 무관 — 최초 계획의 "실린더 다수" 조건은 단일 실린더
     자동 왕복 예제에도 맞게 구현 중 완화) / 속도제어밸브 → "속도제어" / 셔틀·2압밸브
     → "논리 회로(OR/AND) 제어" (구현 중 추가) / 전기 단독 + 릴레이 계열 부하 →
     "릴레이 시퀀스 제어" (구현 중 추가) / 그 외 → 도메인 기반 기본 문구.
   - 조사(을/를)는 목록 마지막 항목의 마지막 한글 음절 종성으로 판정 — 괄호로 끝나는
     부품명("…(스로틀+체크)")도 역방향 탐색으로 정확히 처리.

## Phase 13 — PLC 래더 연속 선도 렌더링 (교육용 LD, XG5000 표기 관례 참고) ✅ 완료 (2026-07-15)

**배경 (사용자 보고)**: 기존에 쓰던 프로그램(XG5000)에 비해 래더 선도가 "단(렁)과
단이 끊겨" 보인다 — 하나로 이어진 사다리(ladder)가 아니라 조각난 블록들로 표현된다.

### 원인 분석 (2026-07-15 실측 — `PlcPanel.tsx` + 브라우저 계측)

1. **좌측 모선(파워 레일)이 렁 단위 조각**: `.plc-rail`이 행마다 별도 조각으로
   그려지고, 렁 사이에 여백 10px + 렁 헤더("렁 0" + 버튼) 16px = **약 28px 공백**에서
   모선이 실제로 끊긴다 (브라우저 측정값). XG5000은 좌측 모선이 프로그램 전체를
   관통하는 연속 세로선이다.
2. **우측 모선이 없다**: 출력 코일이 허공에서 끝난다. XG5000은 우측 모선까지
   연결선이 이어진다.
3. **셀이 점선 박스 + 텍스트 글리프**: 기호가 `┤ ├ P0` 같은 문자열이라 셀 좌우
   경계에 닿지 않는다 — 인접한 요소끼리도 선이 이어져 보이지 않고, 디바이스명이
   기호 오른쪽 인라인이다 (XG5000은 기호 위 중앙).
4. **가로 연결선(hline)도 텍스트** `─────`: 셀 경계에 닿지 않아 떠 있는 조각처럼
   보인다.
5. **vlink(OR 분기)가 CSS 의사요소 반쪽 세로 바**: 분기선이 위·아래 행의 선과
   정확히 만나지 않는다.
6. **통전 모니터가 셀 배경색**: XG5000은 통전 경로를 선/기호 색(파워 플로우)으로
   연속 표시한다.

### 개선 계획 (렌더링 계층만 교체 — 데이터 모델·스캐너 의미 불변)

1. **렁 렌더링을 SVG로 교체 (권장)** — 회로 캔버스와 같은 방식. 렁의 rows×8 그리드를
   SVG 하나로 그리고:
   - 모든 심벌은 **셀 좌우 경계에 닿는 수평선 위에 작도**: `─┤ ├─`, `─┤/├─`,
     `─( )─`, `─[TON T0 3s]─` (기능블록은 작은 박스). 요소가 있는 셀은 항상 선이
     관통한다.
   - **디바이스명은 기호 위 중앙** 텍스트, 타이머/카운터 설정값은 아래.
   - hline은 셀 전체를 관통하는 실선.
   - vlink는 노드 열 x좌표에서 **위 행 중심 → 아래 행 중심을 잇는 실선**.
2. **좌·우 모선을 래더 전체 관통 연속선으로**: `plc-rungs` 컨테이너 높이 전체를
   덮는 세로선 2개(좌·우). 렁 사이 간격 구간에서도 이어진다. 출력 열 오른쪽에
   우측 모선을 신설하고 출력 기호에서 우측 모선까지 연결선을 그린다.
3. **렁 헤더 제거 → 좌측 거터**: 렁 번호를 모선 왼쪽 거터에 표시(XG5000 스텝 번호
   관례), `+행`/`×`(삭제) 버튼은 렁 호버 시 거터에 노출. 렁 사이 여백은 모선이
   이어지는 좁은 간격으로 축소.
4. **편집 그리드 분리**: 점선 셀 경계는 편집 모드에서만 옅게 표시, 시뮬레이션
   실행 중에는 숨김 (규범 선도 표시와 편집 보조 표시의 분리 — 회로도 기호의
   base/overlay 분리 원칙과 동일 방향). 셀 클릭 히트 영역은 유지.
5. **통전 표시를 선 색으로**: 셀 배경 강조 대신, 통전된 구간의 수평선·기호·모선
   조각을 강조색으로 칠한다. `PlcMonitor.nodePower`가 이미 렁별 노드(행×노드 열)
   통전을 제공하므로 선분 색만 바인딩하면 된다 — 스캐너 변경 없음.
6. **편집 편의 — 출력 배치 시 자동 hline**: 출력 요소(coil/set/rst/ton/toff/ctu/ctd)를
   놓을 때 같은 행에서 마지막 논리 요소~출력 열 사이의 **빈 셀만** hline으로 자동
   채운다 (예제 빌더 `rungOf()`와 동일 규칙, XG5000 관례). 주의: 이것은 도통 의미가
   있는 데이터 기록이므로 배치 시 1회만 수행하고 기존 셀은 덮지 않는다.
7. **불변 조건**: `LadderRung`(cells/vlinks) 구조, 스캐너(`plc/scanner.ts`) 의미,
   문서 스키마(v3) 모두 변경 없음. 기존 문서·테스트 144개 그대로 통과해야 한다.
   XG5000 비제휴 고지(패널 내)는 유지.

**완료 기준**: plc-self-holding·plc-reciprocate 예제를 열었을 때 (1) 좌·우 모선이
래더 전체를 끊김 없이 관통하고, (2) 접점→접점→코일이 연속 선으로 연결되어 보이며,

## Phase 15 — 유압 압력제어 부품 보강 (시퀀스·카운터밸런스·어큐뮬레이터) ✅ 완료 (2026-08-26)

**배경**: NCS 유압제어 학습모듈(LM1503010216)의 평가 항목 중 **압력 시퀀스 밸브·
카운터밸런스·어큐뮬레이터**가 현재 미지원이고, 미터인 전용 예제도 없다
(후순위 후보에 등재돼 있던 항목). 유압 수업에서 "압력으로 순서를 만든다"는
개념을 다룰 수 없는 상태여서 보강한다.

### 설계 결정 (2026-08-26 확인)

1. **부하압 캡 — 선택 속성, 기본 꺼짐**: 현재 유체 솔버는 압력원에서 min-cap을
   전파하므로 라인 레벨이 항상 소스 압력과 같다. 그래서 시퀀스 밸브를 그대로
   올리면 P 라인이 처음부터 만압이라 **즉시 열려 두 실린더가 동시에 움직인다** —
   "선행 실린더 완료 → 압력 상승 → 후속 회로 작동"이라는 학습 포인트가 사라진다.
   이를 살리기 위해 실린더에 `loadPressure`(부하압, 기본 0 = 사용 안 함) 속성을
   추가하고, **0이 아니면 그 실린더가 아직 행정을 남긴 방향으로 가압될 때 공급
   유로 전체의 레벨을 부하압으로 제한**한다. 행정 끝에 도달하면 캡이 풀려 소스
   압력까지 상승한다.
   - 유량 방정식이 아니라 **위치·가압 방향이라는 상태 → 기존 levelCap 적용**이므로
     Phase 7 압력 레벨(경로상 최소 캡 전파)과 같은 성격의 준정량 확장이다.
     "정량 해석 도입 금지" 고정 결정은 유지된다.
   - 기본값 0이라 기존 예제 19종과 테스트 208개의 동작은 그대로다. 새 시퀀스
     예제에서만 켠다.
   - 판정은 솔버의 고정점 반복 안에서 직전 반복의 포트 상태 + 현재 위치로 내린다
     (파일럿 밸브가 직전 틱 유체 결과를 쓰는 것과 같은 방식). 따라서 첫 틱부터
     캡이 걸려 "한 틱 만압" 같은 튐이 없다.
2. **압력 조작 밸브는 role 하나로 일반화**: 시퀀스와 카운터밸런스는 "파일럿 압력이
   설정압 이상일 때 열리는 밸브"라는 같은 규칙이고 파일럿 위치와 체크 바이패스
   유무만 다르다. `pressure-pilot-valve` role 하나에 `pilotPort?`(생략 시 내부
   파일럿) + `checkBypass?`로 표현한다 — 부품별 분기 금지 규약 준수.
3. **개방 래치(히스테리시스)**: 부하압 캡과 결합하면 "열림 → 후속 실린더 운동 →
   라인 압력 하락 → 닫힘 → 정지 → 압력 상승 → 열림"의 채터가 생긴다. 실물 압력
   밸브의 히스테리시스에 대응해 **한번 열리면 파일럿 포트가 무압이 될 때까지
   열린 상태를 유지**한다. 릴리프의 `reliefActive`와 같이 솔버가 판정하고 런타임에
   기록한다.
4. **카운터밸런스는 외부 파일럿**: 내부 파일럿(자기 배압)으로 두면 우리 모델에는
   부하가 만드는 배압이 없어 영원히 열리지 않는다. 공급 라인에서 파일럿을 받는
   외부 파일럿 구성으로 두면 **"공급압이 설정압에 도달해야 부하가 내려간다"**는
   교육적 동작이 그대로 성립한다.
5. **어큐뮬레이터는 유한한 유지 시간**: 가압 시 즉시 충전(단순화), 공급이 끊기면
   `holdTime` 동안 선형 방전하며 그동안 라인을 가압한다(레벨 = 충전압 × 잔량).
   서지 흡수·맥동 저감은 표현하지 않는다.

### 구현 범위

1. 실린더 `loadPressure` 속성 + 솔버의 운동 방향 판정·유로 레벨 캡
2. `pressure-pilot-valve` role — 압력 시퀀스 밸브(`hyd.sequence`, 내부 파일럿) ·
   카운터밸런스 밸브(`hyd.counterbalance`, 외부 파일럿 + 체크 바이패스)
3. `accumulator` role — 어큐뮬레이터(`hyd.accumulator`) 충·방전 런타임
4. 기호 SVG 3종 (ISO 1219 관례 참고 교육용 단순화)
5. 예제 4종 — 미터인 속도제어 / 압력 시퀀스 회로 / 카운터밸런스 부하 유지 /
   어큐뮬레이터 압력 유지
6. 골든 테스트 + PRD·ARCHITECTURE·README 갱신

**완료 기준 — 충족**: (1) 시퀀스 예제에서 A 실린더가 **행정을 완료한 뒤에** B가 전진하고,
(2) 카운터밸런스 예제에서 설정압 미만이면 하강하지 않다가 설정압 도달 시 하강하며,
(3) 어큐뮬레이터 예제에서 공급 차단 후 압력계가 서서히 떨어지고 압력 스위치가
설정값에서 떨어지고, (4) 기존 테스트 208개가 그대로 통과하는 것.

### 구현 결과 (2026-08-26)

  실린더 운동 중에는 릴리프가 열리지 않음), 어큐뮬레이터 보조 압력원 + 실제

## Phase 16 — 에디터 조작성 + 기호 표시 정정 + 리밋 스위치 물리화 ✅ 완료 (2026-08-27)

**배경**: 수업 사용 중 나온 개선 요구 6건. 앞의 다섯은 조작성·표시 정정이고, 마지막
둘(양솔 우선순위·리밋 스위치)은 엔진 거동과 데이터 모델을 건드린다.

### 설계 결정 (2026-08-27)

**양솔레노이드 동시 통전 시 우선순위 — 표준이 정하지 않으므로 교육용 모델을 명시 채택**

- KS B 0054는 **기호 표기 표준**이라 동적 거동을 규정하지 않는다. 밸브 쪽 표준
  (ISO 5599 시리즈=치수·인터페이스, ISO 12238=전환시간 측정)도 **동시 통전 시 스풀
  위치를 규정하지 않는다.**
- 제조사 일반 지침은 **양솔 동시 통전 금지**이며 그때 스풀 위치는 **보장되지 않음
  (indeterminate)**. 그래서 실무·자격증 회로는 **인터록(b접점)** 으로 동시 통전을
  막도록 가르친다.
- 소유자의 실기 관찰("전진솔 통전 중 후진솔을 넣으면 후진으로 움직이고, 다시 전진솔을
  줘도 아무 반응 없음")은 인터록으로 앞 신호가 끊겼거나 나중에 인가된 파일럿이 스풀을
  밀어낸 경우로 설명된다 — 표준이 보장하는 동작은 아니다.
- **채택 규칙**: **마지막 상승 에지 우선(last rising edge wins)**. 새로 켜진
  솔레노이드가 스풀을 가져가고, 이미 켜져 있던 신호는 에지가 아니므로 무시한다.
  관찰된 거동과 일치하고, 시뮬레이터에 필수인 **결정적·재현 가능**한 규칙이다.
  현재 구현(`engine.ts` `resolveValvePosition`의 `leftActive && rightActive → 위치 유지`)을
  대체한다.
- **동시 통전은 설계 결함**이므로 상태바 경고 + 실행 전 검증 경고를 함께 띄워
  "인터록을 설계하라"는 교육 메시지를 전달한다. 규칙을 조용히 적용만 하지 않는다.

**리밋 스위치 물리화 — 실린더 양 끝단에 부착 (2026-08-27 소유자 확정)**

- 현재는 논리적 판정만 있다: `cylinderLabel`로 실린더를 이름표 매칭하고 `triggerAt`
  (전진단/후진단)의 행정 끝점에서 접점이 바뀐다. 판정 자체는 실기와 맞지만,
  **장비 뷰에서 리밋 스위치가 실린더와 무관한 위치에 자유 배치**돼 있어 "어디에
  달린 스위치인지"가 보이지 않는다.
- **행정 중간의 임의 위치(0~1)는 도입하지 않는다.** 실기 장비의 리밋은 후진단·전진단
  두 곳에 다는 것이 표준 구성이고, 임의 위치를 열면 속성·마이그레이션·판정 히스테리시스가
  함께 늘어나는데 학습 목표에는 기여하지 않는다.
- 따라서 **속성 추가 없이** `cylinderLabel` + `triggerAt`을 그대로 쓰고, 장비 뷰에서
  **지정 실린더의 해당 끝단에 부착해 렌더**한다. 스키마 변경도 마이그레이션도 없다.
- 부착 대상 실린더를 찾지 못하면(이름표 불일치) 기존 자유 배치로 폴백해 회로가
  깨지지 않게 한다.

## Phase 17 — 무부하 라인 압력 전파 정정 (유체 솔버) ✅ 완료 (2026-08-27)

**배경**: Phase 15 작업 중 발견한 모델 결함이다. 펌프가 **무부하(관통 배기)** 로 돌고
있어도 체크밸브·감압밸브 너머로 격리된 하류 라인에는 **만압이 그대로 전파**된다.
그때는 어큐뮬레이터 예제의 회로 구성을 바꿔 우회했고 원인은 남겨두었다.

**원인**: `solveFluid`는 (1) 가압 전파 → (2) 배기 전파 → (3) 레벨 전파 순으로 계산한 뒤,
**결과 조립 단계에서야** `supply ∧ exhaust`인 넷을 언로딩으로 분류해 그 넷의
`supplyLevel`을 0으로 만든다. 그래서 **그 넷 자신은 0bar로 보고되지만**, 레벨 전파는
이미 끝난 뒤라 하류로 새어 나간 만압은 그대로 남는다. 같은 회로에서 포트 상태는
"배기 0bar"인데 체크밸브 건너편 압력계는 만압을 가리키는 모순이 생긴다.

**영향**: 언로딩 회로(탠덤·오픈 센터 중립, 4/2 무부하)에 체크밸브·감압밸브·어큐뮬레이터가
붙는 구성은 유압 수업에서 흔하다. 학생이 그런 회로를 그리면 압력계·압력 스위치·시퀀스
밸브가 **틀린 값으로 동작**한다. 조작성 문제보다 교육적으로 해롭다.

### 설계 결정

- **언로딩 넷은 레벨을 갖지도, 전달하지도 않는다.** 결과 조립에서만 0으로 덮지 말고
  레벨 전파 자체에서 차단한다. 이미 `portState`가 그 넷을 "배기"로 보고하고 있으므로,
  레벨을 그에 맞추는 **정합성 수정**이지 새 모델 도입이 아니다.
- 구현: 언로딩 판정을 레벨 전파 **앞으로** 옮기고, (a) 소스 시딩에서 언로딩 넷을 제외,
  (b) `relaxLevel`이 언로딩 넷을 통과하지 못하게 막는다.
- 어큐뮬레이터의 충전/방전 판정도 같은 기준으로 맞춘다. 지금은 **원시 가압 전파**
  (`supplyExternal`)만 보므로 무부하 펌프도 "공급 중"으로 읽는다 — 외부 소스만의
  **레벨** 전파 결과로 판정하도록 바꾼다.
- 기존 예제·테스트는 그대로 통과해야 한다. 무부하가 아닌 회로(클로즈드 센터 중립,
  막다른 P 라인 등)의 레벨은 전혀 달라지지 않는다.

**완료 기준 — 충족**: (1) 펌프가 무부하로 도는 회로에서 체크밸브 건너편 압력계가 0을
가리키고, (2) 같은 회로의 어큐뮬레이터가 방전을 시작하며, (3) 릴리프가 무부하 중에는
열리지 않고, (4) 기존 테스트 225개가 그대로 통과하는 것.

### 구현 결과 (2026-08-27)

- 언로딩 판정(`unloaded[n] = exhaust>0 ∧ supply>0`)을 **레벨 전파 앞으로** 옮기고,
  소스 시딩에서 언로딩 넷을 제외했다. `relaxLevel`에 `blocked` 인자를 추가해 언로딩
  넷이 레벨을 **받지도 전달하지도** 않게 했다.
- 결과 조립의 가압 판정을 `!unloaded ∧ supply>0 ∧ level>0`으로 좁혔다. 레벨 전파가
  끊긴 하류가 "가압 0bar"라는 모순 상태로 남지 않고 **갇힘(blocked)** 으로 보고된다.
  `supplyFactor`도 같은 기준을 따르므로 무부하 펌프로는 실린더가 움직이지 않는다.
- 어큐뮬레이터 충전/방전 판정을 **원시 가압 전파 → 외부 소스만의 레벨 전파**로 바꿨다.
  기존 방식은 무부하로 도는 펌프까지 "공급 중"으로 읽어 방전이 시작되지 않았다.
- 테스트 225 → **227개**. 추가한 2건은 정정을 되돌리면 **실제로 실패**함을 확인했다
  (무부하 시 체크밸브 너머 만압 미전파 / 무부하 회로에서 어큐뮬레이터 방전 시작).
- **모델 한계 명시**: 이 솔버는 **갇힌 압력을 기억하지 않는다.** 체크밸브 뒤 막다른
  라인은 공급이 끊기면 0bar(갇힘)로 보고된다 — 압력 유지가 필요한 회로는 어큐뮬레이터를
  쓰는 것이 이 모델의 표현 방식이다. 정정 전에는 무부하 펌프의 압력이 새어 들어와
  "유지되는 것처럼" 보였을 뿐이고, 펌프 상태와 무관하게 항상 만압이라 더 부정확했다.

## Phase 18 — 다중 선택 + 영역 복사·붙여넣기 ✅ 완료 (2026-08-27)

**배경**: Phase 16-3의 복사·붙여넣기는 **부품 한 개**만 복제한다. 수업에서 실제로
복사하고 싶은 것은 "릴레이 한 줄", "실린더+밸브 한 세트"처럼 **배선까지 포함한 덩어리**라
지금 상태로는 반쪽이다.

### 설계 결정

- **선택 모델 확장**: 현재 `Selection`은 단일 `{type, id}`다. 다중 선택을 담을 수 있게
  넓히되, 기존 단일 선택 경로(속성 패널·회전·삭제)가 그대로 동작하도록 호환을 유지한다.
- **영역 선택**: 빈 캔버스를 드래그하면 사각 영역 안의 부품을 모두 선택한다.
  `Shift+클릭`으로 개별 추가·제거.
- **배선 포함 복제**: 선택된 부품 **양끝이 모두 선택 안에 있는 배선만** 함께 복제한다.
  한쪽 끝이 선택 밖인 배선은 복사하지 않는다 — 붙여넣은 사본이 원본 회로에 끼어들어
  의도치 않은 연결을 만들지 않도록.
- 복제한 배선은 새 부품 id로 다시 이어 붙이고 경로를 재계산한다.
- 붙여넣기 1회는 undo 1회로 되돌아간다 (Phase 16-3 규칙 유지).

**완료 기준 — 충족**: (1) 빈 곳 드래그로 여러 부품이 선택되고, (2) `Ctrl+C`/`Ctrl+V`로
부품과 그 사이 배선이 함께 복제되며, (3) 선택 밖으로 나가는 배선은 복제되지 않고,
(4) 붙여넣기 1회가 undo 1회로 취소되며, (5) 단일 선택 동작(속성 편집·회전·삭제)이
그대로 유지되는 것.

### 구현 결과 (2026-08-27)

- **core**: `extractGroup`(선택 안의 부품 + **양끝이 모두 선택 안에 있는 배선**만 추출),
  `pasteGroup`(새 id 부여 후 내부 배선을 `autoWire`로 다시 이어 경로 재계산),
  `getComponentWorldBounds`·`componentsInRect`(회전을 반영한 AABB 교차로 영역 선택).
- **선택 모델**: `Selection`(단일)은 그대로 두고 `selectedIds: string[]`를 더했다.
  다중 선택이 비어 있으면 단일 선택을 쓰는 `selectedComponentIds()` 헬퍼로
  회전·삭제·복사가 두 경로를 함께 처리한다 — **기존 단일 선택 동작은 무변경**.
  `select()`가 두 상태를 동기화하고, 문서 교체·배치 시작·배선 시작에서 함께 비운다.
- **조작**: **Shift + 좌드래그 = 영역 선택**(점선 사각형 표시), **Shift + 부품 클릭 =
  선택 토글**. 좌드래그 팬은 그대로 뒀다 — 학교 노트북에는 중간 버튼이 없는 경우가
  많아 팬 조작을 바꾸는 편이 위험하다. Shift+클릭은 드래그를 시작하지 않는다
  (다중 선택 중 실수로 부품이 끌려가지 않도록).
- **회전·삭제 확장**: 다중 선택 상태에서 `R`·툴바 회전은 선택 전체를 회전하고,
  `Delete`는 선택 전체를 지운다. 각각 undo 1회로 되돌아간다.
- 속성 패널은 다중 선택 시 "부품 N개 선택됨 — Ctrl+C로 복사, R로 회전, Delete로 삭제"를
  안내한다.
- **테스트** 227 → **230개**: 그룹 추출(선택 밖 배선 제외) · 그룹 붙여넣기(새 id·내부
  배선만 재연결·오프셋) · 영역 선택 교차 판정.
- **브라우저 검증**: Shift 드래그로 실린더+밸브 2개 선택 → "부품 2개와 그 사이 배선
  2개를 복사했습니다" → 붙여넣기 후 부품 3→5 · 배선 3→5, undo 1회로 원상복구.
  콘솔 오류 0.

## Phase 19 — 배포 갱신 신뢰성 + 리밋 스위치 기호 재작도 ✅ 완료 (2026-09-01)

**배경 (사용자 보고)**: (1) 어떤 PC에서는 새 배포가 반영되는데 **다른 PC에서는
Ctrl+Shift+R을 눌러도 최신으로 바뀌지 않는다.** (2) 리밋 스위치 기호가 실기 도면과
다르게 보인다.

### 19-1. 배포가 반영되지 않던 원인 (실측)

배포된 사이트를 직접 계측해 원인을 세 가지로 특정했다. 계측 시점에 GitHub Pages
배포는 2시간 42분 전 성공했는데도 브라우저는 **직전 배포 번들**을 실행 중이었고,
서비스 워커 캐시(`hyd-v4`)에 그 번들이 들어 있었다.

1. **서비스 워커가 갱신되지 않았다.** `public/sw.js`는 Vite가 그대로 복사하므로
   배포마다 **내용이 완전히 동일**했다. 브라우저는 바이트가 같은 워커를 "변경 없음"으로
   판정해 새로 설치하지 않는다 — 한 번 설치된 워커가 계속 살아 있었다.
2. **앱 셸이 낡은 채로 고정됐다.** 셸(index.html)을 HTTP 캐시가 섞인 network-first로
   받았고, 캐시 사본이 있으면 **4초 타임아웃**에 걸려 캐시로 넘어갔다. 느린 학교망에서는
   매번 타임아웃 → 오래된 셸 → 셸이 낡으면 **새 해시 자산을 아예 요청하지 않으므로**
   영구히 옛 버전에 묶인다. 계측 중에도 캐시에 없는 URL 요청이 전부 실패했다.
3. **워커 스크립트 자체를 HTTP 캐시로 검사했다.** 등록 시 `updateViaCache`가 기본값
   (`imports`)이라 sw.js 갱신 여부를 캐시된 사본으로 판단했다.

**정정**
- **빌드마다 sw.js가 달라지게 한다** — `vite.config.ts`에 `swVersionStamp` 플러그인을
  추가해 산출물 해시로 `__BUILD_ID__`를 치환한다. 캐시 이름도 `hyd-<빌드ID>`가 되어
  이전 배포 캐시는 activate에서 자동 정리된다.
- **앱 셸은 항상 새로 받는다** — `cache: "no-store"`로 HTTP 캐시를 건너뛰고, 캐시는
  네트워크가 **실패했을 때만** 폴백으로 쓴다(타임아웃 4초 → 8초, 오프라인 지원 유지).
- **해시 자산은 캐시 우선** — 파일명에 내용 해시가 있어 불변이므로 즉시 응답한다.
  셸만 최신이면 항상 올바른 자산을 가리키므로 저속망에서도 옛 버전에 묶이지 않는다.
- **자동 갱신** — `updateViaCache: "none"`으로 등록하고, 로드 직후와 탭이 다시 보일 때
  `update()`를 호출한다. 새 워커가 설치되면 `skip-waiting` 메시지로 즉시 인계시키고,
  `controllerchange`에서 한 번만 새로고침한다. **학생이 Ctrl+Shift+R을 몰라도**
  다음 방문에 최신 화면이 된다.

### 19-2. 리밋 스위치 기호 재작도 (소유자 제공 도면 기준)

소유자가 제공한 실기 도면(A·B 실린더 + LS1~LS4 배치도 + 사다리 회로)을 대조한 결과,
**리밋 스위치는 도면에서 두 가지로 나뉘어 그려진다**는 점이 확인됐다.

| 위치 | 표기 | HYD 대응 |
|---|---|---|
| 배치도 (실린더 위) | 몸체 박스(대각선 분할) + 좌상단 스프링 + 플런저 + **롤러 원** | **장비 뷰** |
| 사다리 회로 | **롤러(⊙) + 기계적 연결 파선 + 접점**, 감지 방향 화살표 | **회로도** |

1차 시도에서 **사다리에도 몸체 박스를 넣어** 회로가 뭉개졌다(소유자 지적: "리밋스위치가
엉켜서 복잡하게 구현되었어"). 도면대로 둘을 분리해 다시 구현했다.

- **회로도**: 몸체 박스를 걷어내고 **⊙ + 파선 + 접점**만 남겼다. 롤러는 도면처럼
  중심점이 있는 이중 원으로, 감지 방향은 **전진단 ↑ / 후진단 ↓** 화살표로 표시한다
  (기존 ▴/▾ 텍스트 대체). 눌리면 롤러에 통전 표시가 들어온다.
- **장비 뷰**: 도면의 배치도 표기를 그대로 — 박스를 **대각선으로 분할**하고 위 칸에
  접점(눌리면 수평으로 붙음), **좌상단 모서리에 비스듬한 복귀 스프링**, 아래로 플런저와
  **롤러 원**. 부착 좌표는 로드 캠 바로 위(후진단 (48,−30) · 전진단 (88,−30))다.
- **실린더 스프라이트**: 도면처럼 로드 끝에 **캠 원**을 추가해 롤러가 무엇에 눌리는지
  보이게 했다.
- 라벨은 두 스위치가 40px 간격으로 붙어 있어 옆 스위치 스프링과 겹치므로 **박스 위
  중앙**으로 옮겼다.

### 19-3. 버전 확인 + 확실한 강제 갱신, 회로도 장치 표시 (2026-09-01 2차 보고 반영)

19-1을 배포한 뒤에도 "새로고침해도 안 바뀐다, PC·브라우저마다 다르게 보인다"는 보고가
이어졌다. 자동 갱신은 **다음 방문부터** 동작하므로 이미 낡은 워커가 깔린 기기에는
즉시 효과가 없고, 강력 새로고침 동작이 브라우저마다 달라(특히 Safari는 단축키로
서비스 워커를 우회하지 않는다) 사용자가 스스로 벗어나기 어렵다.

- **버전 표시**: 빌드 시 커밋 해시를 주입(`__APP_VERSION__`)해 상태바에 `v<해시>`로
  노출한다. "지금 이 화면이 어느 버전인지"를 눈으로 확인할 수 있어야 기기별 차이를
  진단할 수 있다.
- **강제 갱신 버튼**(`⟳ 최신으로`): 브라우저 단축키에 의존하지 않고
  ① 등록된 서비스 워커 전부 해제 ② Cache Storage 전부 삭제 ③ 캐시 무효화 쿼리를 붙여
  재접속 — 세 단계를 직접 수행한다. 어떤 브라우저에서도 통하는 탈출구다.
- **회로도 장치 표시**: 실기 도면은 같은 도면에 배치도(실린더 + 리밋 스위치 몸체)와
  사다리 회로를 함께 그린다. 회로도에도 실린더 위 로드 끝 위치(후진 x=44 · 전진 x=84)에
  장치 몸체를 덧그려 "어느 실린더의 어느 끝에 달렸는지"를 그림으로 보여 준다
  (`getLimitSwitchMarkers` + `LimitSwitchDeviceMarker`, 표시 전용이라 선택·배선 대상 아님).
  기존의 붉은 삼각형 표식은 이것으로 대체하고, 공압 롤러 밸브에만 남겼다.
- **장비 뷰 정리**: 두 스위치가 행정 길이(40px)만큼만 떨어져 있어 몸체를 좁게(26px)
  유지하고, 스프링을 짧게 정리했으며, 눌린 롤러를 강조색으로 칠해 상태가 한눈에 보인다.

**완료 기준 — 충족**: (1) 배포 후 다른 PC에서 별도 조작 없이 다음 방문에 최신 화면이
되고, 즉시 필요하면 `⟳ 최신으로` 버튼으로 어떤 브라우저에서도 벗어날 수 있으며,
(2) 리밋 스위치가 회로도·장비 뷰 모두 도면 형태(박스+스프링+플런저+롤러)로 그려지고
사다리에는 도면대로 ⊙+파선+접점만 남으며, (3) 기존 테스트가 그대로 통과하는 것.
