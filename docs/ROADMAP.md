# 로드맵

각 단계는 "학생이 실제로 써볼 수 있는 상태"를 종료 조건으로 한다. 단계 순서는 의존성 순서다: 공압이 캔버스·배선·유체 솔버의 기반을 만들고, 전기가 연동(솔레노이드·리밋 스위치)을 추가하고, 유압은 유체 솔버를 재사용하고, PLC는 전기 I/O 위에 올라간다.

## Phase 0 — 기반 (에디터 뼈대) ✅ 완료 (2026-07-12)

- Vite + React + TS 프로젝트 셋업, `core/` · `ui/` 구조
- 문서 모델 + JSON 직렬화/역직렬화 (스키마 버전 포함)
- 캔버스: 그리드, 팬/줌, 부품 배치·이동·회전·삭제, 직교 배선, 스냅
- 부품 정의 레지스트리 + 속성 패널 자동 생성
- 파일 저장/불러오기 (.json 다운로드/업로드)
- undo/redo

**완료 기준**: 더미 부품 두 개를 놓고 배선해 저장→불러오기 왕복이 되는 것.

## Phase 1 — 공압 ✅ 완료 (2026-07-13)

- 공압 부품 라이브러리 (PRD 4.1 전체) + ISO 1219 기호 SVG
- 유체 솔버 + 실린더 적분 + 고정 틱 엔진
- 시뮬레이션 모드: 수동 밸브 클릭 조작, 가압 라인 색상, 밸브 스풀·실린더 애니메이션
- 실행 전 검증 (미연결 포트, 압력원 부재)
- 내장 예제: 기초 공압 회로 5~10종 (단동 실린더 직접 제어, 5/2 밸브 왕복, 속도 제어, 셔틀/2압 논리)

**완료 기준**: 순수 공압 시퀀스(공압 파일럿 방식 A+A-)가 작도·시뮬레이션되는 것.

## Phase 2 — 전기 + 전기공압 연동 ✅ 완료 (2026-07-13)

- 전기 부품 라이브러리 (PRD 4.2) + 사다리형 전기 회로도 영역
- 전기 연결성 솔버, 릴레이/타이머/카운터 상태 기계
- 도메인 연동: 솔레노이드→밸브 전환, 실린더 리밋 스위치→접점
- 내장 예제: 자기유지, 인터록, 타이머 회로, 전기공압 A+B+A-B- (공유압기능사 실기 유형)

**완료 기준**: 공유압기능사 실기 유형의 전기공압 시퀀스 회로가 동작하는 것.

## Phase 3 — 유압 ✅ 완료 (2026-07-13)

- 유압 부품 라이브러리 (PRD 4.3 — 4/3 클로즈드/탠덤/오픈 센터 포함), 유체 솔버에 탱크 귀환·중립 센터 타입 반영
- 내장 예제: 유압 기초 회로 (실린더 왕복, 감압+압력 스위치, 미터아웃). 릴리프 압력 상한은 솔버 동작+테스트로 검증 (codex-review H6 반영). 미터인·카운터밸런스 전용 예제는 후순위

**완료 기준**: 4/3 밸브 + 복동 실린더 유압 회로가 전기 제어로 동작하는 것.

## Phase 4 — PLC 래더 (교육용 LD, XG5000 표기 관례 참고) ✅ 완료 (2026-07-13)

- 래더 모델 + 셀 그리드 에디터 (접점, 코일, SET/RST, TON/TOFF/CTU/CTD 기능블록, 렁 편집)
- 스캔 실행기 + P 디바이스 I/O 매핑 테이블 UI
- 모니터 모드 (통전 오버레이)
- 내장 예제: 자기유지, 타이머 시퀀스, 전기공압 회로의 PLC 치환 예제

**완료 기준**: Phase 2의 릴레이 시퀀스 예제를 PLC 래더로 동일하게 재현할 수 있는 것.

## Phase 5 — 장비 뷰 + 마감 ✅ 완료 (2026-07-13)

- 일러스트 장비 뷰 (프로파일 보드): 공압 우선, 회로도와 스플릿 화면 동기화
- 예제 브라우저 정리 (카테고리: 기초 공압 / 전기공압 / 유압 / PLC / 자격증 유형)
- 성능 점검 (부품 100개 60fps), UI 폴리시(한국어 문자열 정리, 단축키, 인쇄용 회로도 내보내기)

**완료 기준**: 수업 1차시 분량의 데모 시나리오를 처음부터 끝까지 시연 가능한 것.

### 구현 노트 (완료 시점 상태)

- 장비 뷰는 공압/전기 주요 부품 16종의 일러스트 스프라이트 제공, 미등록 부품은 기호로 폴백. 뷰포트를 회로도와 공유해 팬/줌 동기화되며 시뮬레이션 중 스프라이트를 직접 클릭해 조작 가능.
- 예제 18종을 카테고리(공압 기초/전기공압/유압/PLC/자격증 유형)로 분류.
- 성능: 부품 100개 + 배선 100개 회로에서 엔진 평균 틱 시간 5ms 미만 (테스트 상시 검증).
- 인쇄용 SVG 내보내기 지원 (그리드 제거, CSS 변수 인라인).
- (기록 당시의 미구현 잔여였던 장비 자유 배치·감압밸브·유압 모터는 Phase 8·7·10에서 구현 완료됨)

## Phase 6 — 변위단계선도 ✅ 완료 (2026-07-13)

- 시뮬레이션 중 실린더별 위치(0~1)를 시간축으로 기록하는 레코더 (core, React 무관)
- 계단형 선도 차트 패널: 실린더별 트랙(이름표 병기), 실행 시 자동 기록·초기화
- 자격증 실기의 시퀀스 설계 검증(A+B+A−B− 파형 확인)이 목적

**완료 기준**: A+B+A−B− 예제 실행 시 두 실린더의 계단 파형이 순서대로 그려지는 것.

## Phase 7 — 압력 레벨 (준정량 최소 확장) + 감압밸브 + 압력 스위치 ✅ 완료 (2026-07-13)

- 유체 솔버가 가압 전파 시 **압력 레벨(bar 수치)**을 함께 전파 — 수치 해석이 아니라 경로상 최소 레벨 전파(min-cap)로, 논리/상태 기반 결정을 유지하는 최소 확장
- 감압밸브(유압): 통과 시 레벨을 설정값으로 제한
- 압력계: 배관 레벨 수치 표시
- 압력 스위치(공압, PRD 4.1 잔여): 유체 포트 압력이 설정 레벨 이상이면 전기 접점 동작 (유체→전기 연동)

**완료 기준**: 파워유닛(40bar) → 감압밸브(20bar) → 압력계가 20을 표시하고, 압력 스위치로 램프가 켜지는 것.

## Phase 8 — 장비 뷰 자유 배치 ✅ 완료 (2026-07-13)

- 문서에 `equipmentLayout`(부품별 장비 뷰 좌표) 추가 — schemaVersion 2 + 마이그레이션
- 장비 뷰에서 스프라이트 드래그로 자유 배치 (편집 모드), 배치 초기화 버튼
- 호스/배선은 이동된 포트 위치 기준으로 재라우팅

**완료 기준**: 장비 뷰에서 부품을 옮겨 저장→불러오기 후 배치가 유지되는 것.

## Phase 9 — PWA + 로컬 저장소 (백엔드 준비) ✅ 완료 (2026-07-13)

- PWA: 매니페스트 + 서비스 워커(정적 자산 캐시)로 오프라인 실행, 설치 가능
- 저장소 어댑터 인터페이스(list/save/load/delete) + 브라우저(localStorage) 구현 — 파일 없이 회로 저장/열기
- **실제 서버(계정·클라우드·과제 배포)는 "백엔드 없음" 고정 결정에 저촉되므로 사용자 확인 전 착수 금지.** 어댑터 인터페이스가 향후 REST 구현의 접점.

**완료 기준**: 브라우저 저장/열기가 동작하고, 프로덕션 빌드가 오프라인에서 로드되는 것.

## Phase 10 — i18n 기반 + 유압 모터 ✅ 완료 (2026-07-13)

- 문자열 리소스 모듈(t(key), ko/en 사전) + 언어 전환 토글 — UI 크롬(툴바·패널·상태바) 우선 적용, 부품·예제 이름은 후속(한국어 유지)
- 유압 모터: 액추에이터 behavior 확장(정/역회전), 기호 회전 애니메이션

**완료 기준**: 언어 토글로 UI 크롬이 영/한 전환되고, 유압 모터가 밸브 방향에 따라 회전 방향을 바꾸는 것.

## Phase 11 — 실행 모드 분화: 연속동작 / 구분동작 ✅ 완료 (2026-07-14)

- **연속동작 실행**: 기존 실행 방식 (50Hz 고정 틱 연속 진행)
- **구분동작 실행(스텝 모드)**: 실린더가 한 "동작"(행정 완료 또는 중간 정지)을 마칠 때마다 시뮬레이션이 자동 일시정지되고, **빈 캔버스 클릭**(또는 [다음 동작] 버튼)으로 다음 동작을 진행
  - 동작 경계 판정: 실린더가 행정 끝(0/1)에 도달하거나, 움직임이 멈춘 채 일정 시간 유지될 때 (core `StepController`, React 무관)
  - **사이클 경계 표시**: 모든 실린더가 초기 위치로 복귀하면 "사이클 완료 — 처음 동작으로 돌아감"을 상태바에 표시 (마지막 동작→처음 동작 전환 지점)
- **변위단계선도 연동**: 동작 경계마다 번호(① ② …) 세로 점선, 사이클 경계는 강조 실선(↻)으로 표기 — 구분동작으로 진행한 시퀀스를 선도에서 단계별로 읽을 수 있게

**완료 기준**: A+A− 예제를 구분동작으로 실행해 클릭마다 A+ / A−가 하나씩 진행되고, A− 완료 시 사이클 경계가 상태바·변위선도에 표시되는 것.

## Phase 12 — 학습 활동 설명 필드 (과제물 JSON 메타데이터) ✅ 완료 (2026-07-15)

**배경**: 학생이 과제물을 .json으로 저장해 제출하면, 교사는 파일을 열어보기 전에는
그 회로가 어떤 학습 활동인지 알 수 없다. 파일 안에 활동 설명이 글로 들어 있으면
교사가 학습자별 누적 자료를 분류·활용할 수 있다.
(예: "제어밸브 및 복동실린더를 활용한 시퀀스 제어", "속도제어 밸브·푸시버튼·릴레이를
활용한 속도제어 회로 구현")

### 설계 결정 (소유자 인터뷰, 2026-07-15)

- **작성 주체 — 자동 초안 + 수정 가능**: 앱이 회로 내용에서 설명 문장을 자동 생성해
  초안으로 제시하고, 학생·교사가 저장 전에 수정할 수 있다. 필드를 비워둔 채 저장하면
  자동 초안을 채워 저장한다 (설명 없는 파일이 생기지 않도록).
- **학습자 식별 정보(이름/학번/반) 전용 필드를 두지 않는다**: 이름·학번을 위한 전용
  입력 필드를 만들지 않고, 자동 생성기도 식별 정보를 만들지 않는다. 제출자 식별은
  파일명·제출 체계(LMS 등)에 위임한다. 이 결정은 문서 포맷의 non-goal로 유지한다.
  단, 학습 활동 설명·회로 제목·부품 이름표는 자유 입력이라 학생이 개인정보를 적을 수는
  있으므로 "포함하지 않는다"는 기술적 보장이 아니라 "전용 필드 없음 + 서버 미전송 +
  자유 입력란 주의 안내"가 정확한 설명이다 (review P1). 파서는 미등록 `meta` 키를
  제거해 조작된 JSON의 숨은 식별 필드가 재직렬화되지 않게 한다.
- **범위 — 포맷 + 입력 UI까지**: 여러 JSON을 일괄 열람하는 교사용 뷰어는 이번
  범위에서 제외하고 후순위 후보에 등재한다.

### 구현 계획

1. **스키마 (v2 → v3)**
   - `meta.learningActivity?: string` 필드 추가 (한국어 설명 문장, 길이 상한 예: 500자).
   - `schemaVersion: 3` + `migrateV2toV3` (v2 문서는 필드 없음 → 빈 값으로 로드,
     다음 저장 때 자동 초안이 채워짐). CLAUDE.md의 "포맷 변경 시 마이그레이션 추가"
     규약과 equipmentLayout(v1→v2) 전례를 따른다.
   - `parseDocument` 검증: 타입(string)·길이 상한. 기존 검증 스타일(propertySchema
     기반 정규화)과 일관되게.
2. **자동 초안 생성기 (core, React 무관)** — `src/core/model/learning-activity.ts`
   - `summarizeLearningActivity(doc): string` — 부품 정의의 role/domain을 집계해
     "[주요 부품 나열]을(를) 활용한 [제어 유형] 회로 구현" 형태의 문장을 조립한다.
     부품은 우선순위 2단계(유체 액추에이터·밸브·능동 elec-load가 우선, 접점·표시등은
     후순위)로 정렬해 배선용 리밋스위치·릴레이접점 다수가 핵심 부품(실린더·밸브)을
     밀어내지 않게 한다. 동력원/배기/분기 역할은 목록에서 제외.
   - 제어 유형 판정 순서(데이터 주도, 부품별 분기 금지): PLC 프로그램 존재 → "PLC 제어"
     / 솔레노이드 밸브 → "전기공압(유압) 시퀀스 제어" / 롤러·리밋 스위치 → "시퀀스
     제어(자동 왕복)" (실린더 개수 무관 — 최초 계획의 "실린더 다수" 조건은 단일 실린더
     자동 왕복 예제에도 맞게 구현 중 완화) / 속도제어밸브 → "속도제어" / 셔틀·2압밸브
     → "논리 회로(OR/AND) 제어" (구현 중 추가) / 전기 단독 + 릴레이 계열 부하 →
     "릴레이 시퀀스 제어" (구현 중 추가) / 그 외 → 도메인 기반 기본 문구.
   - 조사(을/를)는 목록 마지막 항목의 마지막 한글 음절 종성으로 판정 — 괄호로 끝나는
     부품명("…(스로틀+체크)")도 역방향 탐색으로 정확히 처리.
   - 골든 테스트: `src/core/model/__tests__/learning-activity.test.ts` — 판정 분기별

## Phase 13 — PLC 래더 연속 선도 렌더링 (교육용 LD, XG5000 표기 관례 참고) ✅ 완료 (2026-07-15)

**배경 (사용자 보고)**: 기존에 쓰던 프로그램(XG5000)에 비해 래더 선도가 "단(렁)과
단이 끊겨" 보인다 — 하나로 이어진 사다리(ladder)가 아니라 조각난 블록들로 표현된다.

### 원인 분석 (2026-07-15 실측 — `PlcPanel.tsx` + 브라우저 계측)

1. **좌측 모선(파워 레일)이 렁 단위 조각**: `.plc-rail`이 행마다 별도 조각으로
   그려지고, 렁 사이에 여백 10px + 렁 헤더("렁 0" + 버튼) 16px = **약 28px 공백**에서
   모선이 실제로 끊긴다 (브라우저 측정값). XG5000은 좌측 모선이 프로그램 전체를
   관통하는 연속 세로선이다.
2. **우측 모선이 없다**: 출력 코일이 허공에서 끝난다. XG5000은 우측 모선까지
   연결선이 이어진다.
3. **셀이 점선 박스 + 텍스트 글리프**: 기호가 `┤ ├ P0` 같은 문자열이라 셀 좌우
   경계에 닿지 않는다 — 인접한 요소끼리도 선이 이어져 보이지 않고, 디바이스명이
   기호 오른쪽 인라인이다 (XG5000은 기호 위 중앙).
4. **가로 연결선(hline)도 텍스트** `─────`: 셀 경계에 닿지 않아 떠 있는 조각처럼
   보인다.
5. **vlink(OR 분기)가 CSS 의사요소 반쪽 세로 바**: 분기선이 위·아래 행의 선과
   정확히 만나지 않는다.
6. **통전 모니터가 셀 배경색**: XG5000은 통전 경로를 선/기호 색(파워 플로우)으로
   연속 표시한다.

### 개선 계획 (렌더링 계층만 교체 — 데이터 모델·스캐너 의미 불변)

1. **렁 렌더링을 SVG로 교체 (권장)** — 회로 캔버스와 같은 방식. 렁의 rows×8 그리드를
   SVG 하나로 그리고:
   - 모든 심벌은 **셀 좌우 경계에 닿는 수평선 위에 작도**: `─┤ ├─`, `─┤/├─`,
     `─( )─`, `─[TON T0 3s]─` (기능블록은 작은 박스). 요소가 있는 셀은 항상 선이
     관통한다.
   - **디바이스명은 기호 위 중앙** 텍스트, 타이머/카운터 설정값은 아래.
   - hline은 셀 전체를 관통하는 실선.
   - vlink는 노드 열 x좌표에서 **위 행 중심 → 아래 행 중심을 잇는 실선**.
2. **좌·우 모선을 래더 전체 관통 연속선으로**: `plc-rungs` 컨테이너 높이 전체를
   덮는 세로선 2개(좌·우). 렁 사이 간격 구간에서도 이어진다. 출력 열 오른쪽에
   우측 모선을 신설하고 출력 기호에서 우측 모선까지 연결선을 그린다.
3. **렁 헤더 제거 → 좌측 거터**: 렁 번호를 모선 왼쪽 거터에 표시(XG5000 스텝 번호
   관례), `+행`/`×`(삭제) 버튼은 렁 호버 시 거터에 노출. 렁 사이 여백은 모선이
   이어지는 좁은 간격으로 축소.
4. **편집 그리드 분리**: 점선 셀 경계는 편집 모드에서만 옅게 표시, 시뮬레이션
   실행 중에는 숨김 (규범 선도 표시와 편집 보조 표시의 분리 — 회로도 기호의
   base/overlay 분리 원칙과 동일 방향). 셀 클릭 히트 영역은 유지.
5. **통전 표시를 선 색으로**: 셀 배경 강조 대신, 통전된 구간의 수평선·기호·모선
   조각을 강조색으로 칠한다. `PlcMonitor.nodePower`가 이미 렁별 노드(행×노드 열)
   통전을 제공하므로 선분 색만 바인딩하면 된다 — 스캐너 변경 없음.
6. **편집 편의 — 출력 배치 시 자동 hline**: 출력 요소(coil/set/rst/ton/toff/ctu/ctd)를
   놓을 때 같은 행에서 마지막 논리 요소~출력 열 사이의 **빈 셀만** hline으로 자동
   채운다 (예제 빌더 `rungOf()`와 동일 규칙, XG5000 관례). 주의: 이것은 도통 의미가
   있는 데이터 기록이므로 배치 시 1회만 수행하고 기존 셀은 덮지 않는다.
7. **불변 조건**: `LadderRung`(cells/vlinks) 구조, 스캐너(`plc/scanner.ts`) 의미,
   문서 스키마(v3) 모두 변경 없음. 기존 문서·테스트 144개 그대로 통과해야 한다.
   XG5000 비제휴 고지(패널 내)는 유지.

**완료 기준**: plc-self-holding·plc-reciprocate 예제를 열었을 때 (1) 좌·우 모선이
래더 전체를 끊김 없이 관통하고, (2) 접점→접점→코일이 연속 선으로 연결되어 보이며,

3. **PLC** (14-3): P/M 마지막 자리 16진 허용(P0000A — 중간 자리는 거부), ioMap
   채널 의미 검증(스테이션=채널 필수·방향별 목록, 단채널 부품=채널 불허),
   runPlcScan 채널 입출력(센서 이미지 부품당 1회 계산, 채널 출력은 전기 고정점
   재실행 제외), setMpsButton API. domain "automation" + `auto.mps-station` 등록.
4. **UI** (14-4): 회로도 단자대 블록(단자 번호=어드레스 마지막 자리 0~F/10~19),
   장비 뷰 스프라이트(매거진 적재·실린더 4·드릴 회전·벨트 무늬 이동·물품
   재질색·박스 계수·램프·PB 패널 클릭 조작), ioMap 채널 select(방향 전환 시
   재설정, 단채널 전환 시 채널 제거).
5. **예제·검증** (14-5): 예제 19 "MPS 기본동작" — 수업자료 기본동작 래더 재현
   (스텝 체인 M11~M17, 판별 M100/M101, T0018/T0019, 출력부. 실기 T0019=3.5s는
   시뮬레이터 컨베이어 속도에 맞춰 5.1s로 조정 명기). I/O 20점 전체 매핑.
   골든 테스트: 금속→배출박스 / 비금속→저장박스. 심화 1~3단계는 학생 실습
   과제로 남김(같은 설비에서 래더만 교체).
